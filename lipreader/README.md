# lipreader

A visual speech recognition (lip-reading) prototype: given a VOD (video-on-demand)
clip and the language its speakers use, it analyzes the video **only** —
any audio track is never touched — and returns the **3 most likely
dialogue transcriptions**, ranked by probability.

```
video (file or URL) → frames → per-frame mouth crop (MediaPipe) → visual model → CTC beam search → top-3 texts
```

## Status: pipeline works end-to-end, model is untrained

Every stage runs and is tested (`tests/test_pipeline_smoke.py`): video
decoding, face/mouth detection and cropping, the neural network forward
pass, and CTC beam-search decoding into ranked text candidates. What's
**not** included is a trained model — real lip-reading needs training on
hours of aligned video/transcript data (e.g. the LRS3 or LRW datasets)
with real GPU time, which isn't something achievable in this environment.
`src/lipreader/model.py` documents this and exposes `load_pretrained()` as
the plug-in point for real weights (e.g. a converted Auto-AVSR checkpoint)
once you have one. Until then, output text is not meaningful — it proves
the mechanics work, not the accuracy.

Even a properly trained model won't be highly accurate: general lip-reading
is an open research problem — state-of-the-art models trained on huge
datasets top out around 40-60% word accuracy on clean, front-facing test
footage, and do worse on real broadcast angles/motion. Treat any output as
a set of guesses, not a transcript.

## Sandbox network constraints (read before debugging "it doesn't work")

This was built inside an environment whose egress policy blocks
`youtube.com`, `huggingface.co`, and `drive.google.com`. That means, in
*this* sandbox:

- `--source` as a YouTube URL cannot actually be downloaded here (the
  `yt-dlp` code path is written and should work in an unrestricted
  environment — it's just untestable from here).
- No pretrained lip-reading checkpoint could be fetched (Auto-AVSR and
  similar are hosted on HF Hub / Google Drive).

`github.com`, `pypi.org`, and `storage.googleapis.com` (where MediaPipe's
face landmark model lives) were reachable, which is how the working parts
of this pipeline were built and tested — using a local video file
(`tests/fixtures/synthetic_test_clip.mp4`, generated by
`scripts/make_synthetic_test_clip.py` from a single still face photo) as
the smoke-test input.

**Next step to get a real result**: run this on a machine that can reach
YouTube (for input) and a place to source real pretrained lip-reading
weights, with an actual clip of someone talking.

## Setup

```bash
cd lipreader
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

The MediaPipe face landmark model (`assets/face_landmarker.task`) is
already bundled in this repo, so no download is needed for that part.

## Usage

```bash
PYTHONPATH=src python3 -m lipreader.cli <video-path-or-url> --language es --top-k 3
# optional: --checkpoint path/to/pretrained_weights.pt
```

`--language` selects the character vocabulary used for decoding (currently
`en`, `es` — see `src/lipreader/vocab.py`).

## Layout

- `src/lipreader/video_source.py` — resolve a local path or URL (via
  `yt-dlp`) to decoded video frames. Audio is never read.
- `src/lipreader/mouth_roi.py` — per-frame face/mouth detection and
  cropping via MediaPipe's `FaceLandmarker`.
- `src/lipreader/model.py` — 3D-CNN + BiGRU + CTC visual speech model
  (untrained scaffold; see above).
- `src/lipreader/decode.py` — CTC prefix beam search, returns top-K ranked
  text candidates instead of a single greedy guess.
- `src/lipreader/vocab.py` — per-language character vocabularies.
- `src/lipreader/transcribe.py` / `cli.py` — orchestration and CLI entrypoint.
- `scripts/make_synthetic_test_clip.py` — builds the local smoke-test fixture.
- `tests/test_pipeline_smoke.py` — mechanics tests (not accuracy tests).

## Run tests

```bash
PYTHONPATH=src python3 -m pytest tests/
```
